# SkillMem Agent V1 当前边界（Stage 2）

B1是本机电商售后模拟系统的研究基线，不是生产支付系统。业务订单均来自合成夹具，身份Header/员工共享Key仍是演示鉴权。

- **持久化范围**：同一文件路径下，SQLite保存业务完整快照、退款/取消/工单幂等回执、审批决定与结果、执行次数及LangGraph checkpoint。业务事务与checkpoint是两个提交边界，通过稳定业务回执处理跨边界重放；没有宣称分布式事务或真实支付Exactly Once。
- **重启证据**：独立子进程完成订单操作后重启，以及在退款事务提交后`os._exit`退出、下一进程恢复审批，都已测试。未测试主机断电、文件损坏、备份恢复、磁盘满、NFS或多主机部署。
- **并发**：同一个Service实例串行所有会话，以避免共享checkpoint连接竞争；不同实例/进程对同DB/thread用POSIX flock串行，业务写事务还由SQLite序列化。会话锁文件会累积，当前小规模评测未做回收机制。不同会话共享业务Store快照会增加写入竞争，不适合大规模订单库。
- **超时**：同步本地工具在进入/提交事务前检查截止时间，超时不提交副作用，不遗留后台写线程。它不是可杀死任意阻塞Python函数的硬墙钟中断；模型SDK自己的网络超时与SQLite busy timeout仍影响返回时间。不能将5秒配置宣传为所有故障下5秒必返回。
- **恢复**：批准/拒绝决定一旦写入不可覆盖。异常保留resolving/retryable；用相同approval_id和相同决定恢复。同一审批重复决定返回缓存结果；不同决定409。非审批基础设施故障使用SupportService.retry_turn。模型/工具明确终止后可能返回failed，即使业务退款已提交；业务真实状态以Store/回执为准，不以回复状态退款或撤销。
- **历史迁移**：B0业务记录未持久化，因此不能从其checkpoint重建已经发生的退款。B1拒绝直接打开有会话的旧B0数据库，必须使用新数据库或人工对账后制定迁移；B0也不能打开B1数据库。
- **工具协议**：多调用全部返回错误且本轮零业务执行。未知工具、非法/额外参数可由模型在剩余预算内修正；丢失/重复call ID不可安全配对时明确终止，需新会话。没有Skill级工具路由。
- **重试与预算**：B1禁止SDK内部重试，只允许有明确预算的后续模型轮次；副作用无自动重试。每用户轮次8模型/8工具尝试默认值可显式配置。审批等待不消耗墙钟窗口，但恢复不重置次数。用户新轮次会获得新预算，此机制不是账户级限流或美元费用上限。
- **评测**：153项pytest及B0/B1兼容任务均为离线/Mock；Stage 2没有新真实API结果。Oracle仍有固定事实/词语匹配局限，不能全面识别否定或矛盾。中文只添加政策关键词别名，不代表完整中文多轮评测通过。
- **日志**：Trace原始对话和业务快照只在忽略目录；Key过滤不等于通用PII匿名化。公开artifact只保留合成夹具脱敏投影。无日志写入失败自动业务重放。
- **后续范围**：尚无Structured TaskMemory、Context Compression、Skill Routing、Planning、RAG或多Agent；可靠性修复不得归因为这些后续功能的收益。
